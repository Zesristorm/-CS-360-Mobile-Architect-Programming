# -CS-360-Mobile-Architect-Programming

# About the Project
I developed an event-tracking app designed to help users keep up with their schedules in a simple and organized way. The main goal of the app was to give users one place to create, view, edit, and delete events while also making it easy to see what is coming up. This app was built to address the need for a planner that feels clear and easy to use instead of overwhelming. It was especially meant for users who want a straightforward way to manage daily events, appointments, and reminders without extra clutter.

# User Needs and App Goals
To support those user needs, the app included several important screens and features. The login screen allowed users to sign in securely and keep their own events separate from other users. The main week view gave users a quick look at their upcoming events for the current week, while the full calendar view let them look at events by date. The add and edit event screen allowed users to enter the event name, date, time, and details, while also giving them the option to delete an event if needed. I also included features like checkboxes to mark events as completed and icons to make different event types easier to recognize. My UI designs kept users in mind by focusing on simplicity, readability, and ease of movement between screens. I wanted the app to feel friendly and not confusing, so I used a clean layout, clear buttons, and a planner style that made the app feel inviting. I think the designs were successful because the app stayed functional while still feeling personal and easy to understand.

# Coding Process
When coding the app, I approached it one step at a time. I first made sure the basic structure worked, such as navigation between screens, database setup, and user login. After that, I added features piece by piece, testing each one before moving on. This helped me avoid getting lost and made it easier to spot problems. I used Java and SQLite in Android Studio, and I relied a lot on breaking problems into smaller parts instead of trying to solve everything at once. I also reused code where it made sense, such as using shared database methods to manage events. This is a strategy I can use again in the future because it keeps projects more organized and easier to fix when something goes wrong.

# Testing and Functionality
To make sure the code was functional, I tested the app often while building it. I checked that users could create accounts, log in, add events, edit events, delete events, and mark them as completed. I also tested that events only showed up for the correct logged-in user and that changes appeared correctly in both the week view and the calendar view. This process was important because it helped reveal problems that were not obvious at first, such as events showing under the wrong account, deleted events still appearing, or dates not lining up the way they should. Testing helped me see where the app was strong and where I needed to make improvements.

# Challenges and Problem Solving
Looking at the full design and development process, one place where I had to innovate was in solving layout and event display challenges. I had to make decisions about how the weekly event cards should look, where the delete option should go, and how to make the app feel organized without adding too much to the screen. I changed parts of the design as I worked, such as moving delete into the edit screen and using a checkbox for completion, because those choices made the app cleaner and easier to use. I also had to work through issues with the week view not lining up correctly and old events still appearing, which pushed me to think more carefully about how the app handled dates and database updates.

# Strengths and Successes
The part of my app where I was most successful in showing my knowledge, skills, and experience was the design. Even though I still had to learn how to fully implement the app through coding, I was able to turn my idea into a cute pastel planner design that matched the feeling I wanted the app to have. I put a lot of thought into making the app look soft, organized, and welcoming instead of plain or overwhelming. This showed my ability to design with the user in mind, because I wanted the app to feel simple to use while also being visually appealing. I think this was one of my strongest areas because it showed that I could turn an idea into a creative and user-friendly design.
